== Q1  What problem does this bounded context solve, and for whom?

The system is called *Leihgut* (German: lent goods).
It replaces a paper ring-binder and cash-deposit process for the association
*Bibliothek der Dinge* (Library of Things), which lends tools and equipment to members.
Known failures of the current process: deposits miscalculated, maintenance-due items
issued anyway, reservations broken by concurrent extensions.

[ANSWERED] +
Name: `Leihgut — Ausleihsystem der Bibliothek der Dinge`. +
Described as a programming exercise in agentic coding, domain: equipment lending for a
non-profit association ("Verein"). +
Evidence: `README.adoc:1`, `pyproject.toml:3`

=== Q1.2  Primary users

[ANSWERED] +
Three user roles are named in README and enforced in code:

* *Karim, Thekendienst* (counter staff) — issues items, accepts returns, extends loans.

* *Rolf, Werkstattwart* (maintenance technician) — inspects returned items, performs

=== Q3.4  Solution strategy

[ANSWERED] +
Four structural decisions, each derivable from code:

1. *Hexagonal architecture* (Ports & Adapters): domain ← anwendungskern ← ports ← adapters. +
2. *Immutable domain objects*: all entities use `@dataclass(frozen=True)`. +
3. *Discriminated union results*: application services return `Success | Error1 | Error2`
   — no exception-based control flow for expected domain failures. +
4. *IOSP* (Integration-Operation Separation Principle): every service file has a pure
   `_*_pruefen()` function (no ports) separated from the integration function. +

Evidence: `ausleihe_service.py:1-8`, `domain/gegenstand.py:22`,
`ausleihe_service.py:77-83`, `katalog_service.py:1-6`

== Q4  What quality goals drive the design?

=== Q4.1  Functional suitability

[ANSWERED] +
All 10 use cases are implemented. Application-level validation rules are duplicated as
DB-level constraints (CHECK, unique indexes) as a second barrier. +
Quality scenario: Given any well-formed input to any endpoint, the returned state
matches all BR-KAT/BR-AUS/BR-RUP/BR-KAU/BR-EIN/BR-VOR/BR-VER/BR-WAR rules. +
Evidence: `schema.sql` (all CHECKs and indexes), `anwendungskern/` (all services)

=== Q4.2  Reliability

==== Q4.2.1  TOCTOU protection (concurrent double-issue)

[ANSWERED] +
Quality scenario: When two requests concurrently issue the same item, exactly one
succeeds; the other receives 409 GEGENSTAND_NICHT_VERFUEGBAR. Mechanism: `BEGIN
IMMEDIATE` acquires write lock before insert; partial unique index
`ux_ausleihe_aktiv_je_gegenstand` is the second barrier; SQLite `IntegrityError`
is caught and translated to `NebenlaeufigeAusgabeAbgelehnt`. +
Evidence: `adapters/persistence/sqlite_ausleihe_repository.py:34-60`,
`schema.sql:55-59`

==== Q4.2.2  Atomic multi-aggregate write (inspection close)

[ANSWERED] +
Quality scenario: If any write in the inspection-close sequence fails, no partial
state is committed. Mechanism: `PruefabschlussRepository.abschliessen()` wraps all
six writes in one `BEGIN IMMEDIATE … COMMIT`. +
Evidence: `ports/pruefabschluss_repository.py:22-34`

==== Q4.2.3  Audit-log immutability

[ANSWERED] +
Quality scenario: No application code path can silently UPDATE or DELETE an audit
entry. Mechanism: SQLite `BEFORE UPDATE` and `BEFORE DELETE` triggers call
`RAISE(ABORT, …)`. +
Evidence: `schema.sql:96-106`

==== Q4.2.4  Audit-log effective immutability vs. retention

[ANSWERED] — with known gap (see Q5.3.4) +
The `cleanup_audit_log()` function writes a `retention_cleanup` record but cannot
actually delete rows (triggers prevent it). The log grows without bound.
Evidence: `anwendungskern/audit_retention_service.py:52-55`

=== Q4.3  Usability

[OPEN] +
Category: quality-goals +
Ask role: Product Owner +
No usability targets are in the code. The demo frontend exists
(`adapters/rest/static/index.html`) but there are no acceptance criteria for response
time, error message clarity, or UI flows.

=== Q4.4  Performance efficiency

[OPEN] +
Category: quality-goals +
Ask role: Product Owner / Architect +
No response-time SLA, throughput target or latency budget is derivable from the code.
Context from README: ~400 items, ~800 members, open Tuesdays and Saturdays — very low
concurrency. SQLite is likely adequate but no target numbers are stated, so they cannot
be written as [ANSWERED] quality scenarios.

=== Q4.5  Security

[ANSWERED] +
Quality scenario (preventive): Any request with an absent or unrecognised `X-Rolle`
header is rejected 403 before any application service is called. +
Quality scenario (detective): Every state-changing operation produces an immutable
audit entry with role attribution in the same DB transaction. +
Known accepted risks: T-004 (roles unverified), R-002 (filesystem-level tampering).
No encryption, no token auth, no rate limiting. +
Evidence: `adapters/rest/rollen.py:13-25`, `schema.sql:96-106`, `rollen.py:7-8`

=== Q4.6  Maintainability

==== Q4.6.1  IOSP — Operations/Integration separation

[ANSWERED] +
Quality scenario: Any validation rule change affects only the `_*_pruefen()` pure
function; no repository interaction is needed to test it. +
Metric: Every service file has at least one `_*_pruefen()` Operation and one
Integration function. +
Evidence: `ausleihe_service.py:107-139` (`_ausgabe_pruefen`),
`pruefung_service.py:68-80` (`_pruefung_pruefen`),
`katalog_service.py:59-75` (`_kategorie_werte_pruefen`)

==== Q4.6.2  Testability via FakeClock

[ANSWERED] +
Quality scenario: Any date-dependent test runs deterministically without mocking
`datetime.now`. Mechanism: all services receive a `Clock` port; tests substitute
`FakeClock("2026-08-18T10:00:00")`. +
Evidence: `tests/fakes.py:1-8`, `ports/clock.py:14-16`

==== Q4.6.3  Immutable domain objects

[ANSWERED] +
All domain types use `@dataclass(frozen=True)`. State transitions produce new objects
rather than mutating existing ones. +
Evidence: `domain/gegenstand.py:22`, `domain/ausleihe.py:21`,
`domain/kategorie.py:9`, etc.

[ANSWERED] +

==== Q5.1.4  Bug: clock.jetzt().strftime() called on str

[ANSWERED] +

`heute = clock.jetzt().strftime("%Y-%m-%d")` +
`Clock.jetzt()` returns a `str`, not a `datetime`. Calling `.strftime()` on a string

==== Q5.1.6  Bug: audit_retention_service.py calls jetzt() as datetime

[ANSWERED] +
`anwendungskern/audit_retention_service.py:58` assigns `jetzt = clock.jetzt()`, then
line 61 performs `jetzt - timedelta(days=policy.hot_days)` and line 100 calls
`jetzt.isoformat()`. Both operations assume `jetzt` is a `datetime` object, but
`Clock.jetzt()` returns `str`. This will raise `TypeError` at runtime when the cleanup
endpoint is called. +
Evidence: `anwendungskern/audit_retention_service.py:58-61, 100`,
`ports/clock.py:15`

==== Q5.1.7  verlust_service.py directly imports sqlite3 (ADR-002 violation)

[ANSWERED] +
`anwendungskern/verlust_service.py:6` imports `sqlite3` and at line 49 accepts a raw

Evidence: `anwendungskern/verlust_service.py:6, 49`
