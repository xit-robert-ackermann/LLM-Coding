== 1  Problem Statement

The non-profit association *Bibliothek der Dinge* (Library of Things) lends tools and
equipment — power drills, projectors, cargo bikes, chainsaws, sewing machines and
roughly 400 other items — to approximately 800 members.
The association is open on Tuesdays and Saturdays.

The current process uses a paper ring-binder for loan records and cash for deposits.
Three classes of failure occur regularly
[`README.adoc:17-23`]:

. *Deposit errors* — counter staff calculate the refundable deposit by hand; amounts
  are often wrong or applied inconsistently.
. *Maintenance violations* — items that have reached their inspection threshold are
  issued again because no check is performed at the counter.
. *Reservation failures* — a member reserves an item, but a different member extends
  an active loan in the meantime, breaking the reservation order.

The system *Leihgut* is built to eliminate these three failure modes.

== 2  Target Users (Personas)

Three roles are named in the product description and enforced in the code
[`README.adoc:44-48`, `adapters/rest/app.py:270-274`]:

=== 2.1  Karim — Thekendienst (Counter Staff)

Karim volunteers at the front desk.
He needs to know instantly whether a given item may be issued and for how long,
without calculating the deposit himself.
He handles checkouts, returns, and loan extensions.

=== 2.2  Sabine — Mitglied (Member)

Sabine is a regular member.
She checks availability before coming in and places reservations on categories that
are currently fully lent out.

=== 2.3  Rolf — Werkstattwart (Maintenance Technician)

Rolf manages the workshop.
He inspects items after return, records damage, decides on deposit deductions, retires
worn-out items, performs maintenance, and manages training certifications for items
that require instruction before use.

=== 2.4  Administrator

A fourth role (`admin`) manages the audit-log retention endpoint.
No persona description is available in the current documentation.

== 3  Goals

The following goals are derivable from the problem statement and the rules encoded in
the system [`README.adoc:17-42`]:

[cols="1,4", options="header"]
|===
| Goal | Description
| G-01 | Counter staff can determine in real time whether an item is issuable and what the deposit is, without manual calculation.
| G-02 | Every deposit movement is recorded and traceable; the deposit amount is always derived from the same rule.
| G-03 | Items that have reached their maintenance threshold cannot be issued until the maintenance cycle is completed.
| G-04 | Reservations are honoured in FIFO order; no extension can displace a waiting member.
| G-05 | Every state change to an item, loan, or training is auditable — who changed what, when, in which role.
|===

== 5  Scope

=== 5.1  In scope (Release 1)

The following capabilities are implemented and tested
[`anwendungskern/` directory, `adapters/rest/app.py`]:

[cols="1,3", options="header"]
|===
| Use Case | Summary
| UC-01 | Issue an item to a member (validate state, member lock, limit, training)
| UC-02 | Extend an active loan (once per loan; not overdue; no open reservation)
| UC-03 | Accept a return; move item to inspection
| UC-04 | Complete inspection; record defects; calculate deposit deduction; close loan
| UC-05 | Place a category reservation (FIFO waitlist)
| UC-06 | Record an item as lost; retire item; retain full deposit
| UC-07 | Record a training certification for a member/category pair
| UC-08 | Revoke a training certification
| UC-09 | Manage catalogue (create/update categories and items)
| UC-10 | Check item availability (read-only)
|===

=== 5.2  Out of scope

* *Member management* — member IDs are plain text values; no member CRUD, no member
  profile, no member registration.
  The origin of valid member IDs is deferred
  [`schema.sql:63-64`].
* *Web user interface* — a demo frontend (`adapters/rest/static/`) exists for
  demonstration purposes but has no acceptance criteria and is not a deliverable.
* *Authentication and login* — roles are passed as an unverified `X-Rolle` HTTP
  header; this is an explicit, documented constraint (see Section 7).
* *Email or push notifications* — not implemented.
* *Multi-organisation tenancy* — single association only.

== 6  Constraints

The following constraints are explicitly documented and enforced in code
[`README.adoc:52-59`, `pyproject.toml:4-11`]:

[cols="2,4", options="header"]
|===
| Constraint | Detail
| *Single process* | The system runs as one locally startable process; no external services.
| *No authentication* | Roles are passed via the `X-Rolle` request header and are not
cryptographically verified. This is a deliberate design choice, not a temporary gap.
| *No web UI* | A REST API covers all use cases. A static demo frontend exists for
exploration only.
| *SQLite 3* | Persistence is a single SQLite file. No external database server.
| *Python ≥ 3.11* | The codebase uses union type syntax (`X \| Y`) introduced in 3.10
and requires at least Python 3.11.
| *Replaceable clock* | All date-dependent rules use an injectable `Clock` port so that
loan deadlines, overdue checks, and reservation timestamps can be set to a fixed value
in tests.
|===

== 7  Known Risks and Accepted Limitations

The following risks are explicitly acknowledged in the codebase:

* *T-004 / R-001 — Unverified roles*: Any HTTP client that knows the header name can
  claim any role. Mitigated procedurally (internal network).
  [`adapters/rest/rollen.py:7-8`]
* *R-002 — Audit log file-system access*: SQLite triggers prevent SQL-level tampering
  of the audit log, but direct file-system access to the `.sqlite` file bypasses this
  control.
  [`schema.sql:93-95`]

== 8  Known Technical Gaps (Selected)

The following gaps are in the codebase and must be resolved before the system is
used in production:

[cols="1,3,2", options="header"]
|===
| Ref | Gap | Evidence
| TD-01 | `ausleihe_verlaengern()` calls `clock.jetzt().strftime(…)` on a `str` — crashes at runtime. | `anwendungskern/verlaengerung_service.py:122`
| TD-02 | `audit_retention_service.py` calls arithmetic on the `str` returned by `clock.jetzt()` — crashes at runtime. | `anwendungskern/audit_retention_service.py:58-61`
| TD-03 | Loan extension does not check for open reservations (VormerkungOffen guard commented out). | `anwendungskern/verlaengerung_service.py:128-131`
| TD-04 | Member-lock check in reservation endpoint is a hardcoded empty list. | `adapters/rest/app.py:406`
| TD-05 | Catalogue changes (UC-09) produce no audit entries. | `anwendungskern/katalog_service.py` (no audit_log import)
| TD-06 | `verlust_service.py` imports `sqlite3` directly, violating the port isolation principle. | `anwendungskern/verlust_service.py:6`
| TD-07 | Audit-log cleanup marks old records but cannot delete them; log grows without bound. | `anwendungskern/audit_retention_service.py:52-55`
|===
