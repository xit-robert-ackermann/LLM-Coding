==== Persona Use Case

[cols="1,3"]
|===
|Feld |Inhalt

|Use Case ID
|UC-01

|Name
|Gegenstand ausleihen

|Primary Actor
|Karim (Thekendienst)

|Stakeholders and Interests
a|
* *Thekendienst* — will in dreißig Sekunden wissen, ob ein Gegenstand herausgegeben werden darf, ohne die Kaution im Kopf ausrechnen zu müssen.
* *Mitglied* — will den reservierten oder verfügbaren Gegenstand erhalten.
* *Verein* — will sicherstellen, dass nur berechtigte Mitglieder ausgabefähige Gegenstände erhalten und die Kaution korrekt hinterlegt wird.
* *Wart* — will, dass einweisungspflichtige Geräte nicht ohne Nachweis ausgegeben werden.

|Trigger
|Ein Mitglied erscheint an der Theke und nennt die Inventarnummer des gewünschten Gegenstands sowie seine Mitglieds-ID.

|Preconditions
a|
* Karim ist mit der Rolle `thekendienst` am System angemeldet (`X-Rolle: thekendienst`).
* Das System ist erreichbar.

|Main Success Scenario
a|
1. Karim gibt die Mitglieds-ID und die Inventarnummer in das System ein.
2. Das System prüft, ob die Mitglieds-ID bekannt ist.
3. Das System prüft, ob die Inventarnummer bekannt ist.
4. Das System prüft, ob der Gegenstand verfügbar oder für dieses Mitglied reserviert ist (BR-007).
5. Das System prüft, dass der Gegenstand nicht wartungsfällig ist (BR-026).
6. Das System prüft, dass das Mitglied nicht gesperrt ist (BR-009, BR-034, BR-035).
7. Das System prüft, dass das Mitglied weniger als drei offene Ausleihen hat (BR-008).
8. Falls die Kategorie einweisungspflichtig ist: Das System prüft, dass für das Mitglied und diese Kategorie eine Einweisung vorliegt (BR-010).
9. Das System legt eine neue Ausleihe an (status: OFFEN, ausgabeDatum: heute, rueckgabeFrist: heute + Kategorie.leihdauerTage, verlaengert: false).
10. Das System setzt den Gegenstand auf AUSGELIEHEN.
11. Das System berechnet die Kaution (20 % des Wiederbeschaffungswerts, min 5, max 100 Euro, kaufmännisch gerundet) und legt eine Kautionsbewegung HINTERLEGUNG an (BR-004, BR-011, BR-020, BR-022).
12. Falls der Gegenstand vorher RESERVIERT war: Das System setzt die Reservierung auf ABGEHOLT.
13. Das System gibt die Ausleih-Bestätigung mit Rückgabefrist und Kautionsbetrag zurück (HTTP 201).
14. Karim übergibt den Gegenstand an das Mitglied und nennt die Rückgabefrist.

|Extensions
a|
*4a. Gegenstand nicht verfügbar:* +
Der Gegenstand hat den Status AUSGELIEHEN oder RESERVIERT für ein anderes Mitglied. +
→ Das System antwortet mit 409 GEGENSTAND_NICHT_VERFUEGBAR. +
→ Use Case endet ohne Ausgabe.

*5a. Gegenstand wartungsfällig:* +
Der Gegenstand hat den Status WARTUNGSFAELLIG. +
→ Das System antwortet mit 409 GEGENSTAND_WARTUNGSFAELLIG. +
→ Use Case endet ohne Ausgabe. +
→ Karim informiert das Mitglied; der Wart muss die Wartung abschließen.

*6a. Mitglied gesperrt:* +
Das Mitglied hat mindestens eine überfällige Ausleihe (BR-034, BR-035). +
→ Das System antwortet mit 409 MITGLIED_GESPERRT. +
→ Use Case endet ohne Ausgabe. +
→ Karim fordert das Mitglied auf, die überfälligen Gegenstände zurückzugeben.

*7a. Maximale Ausleihzahl erreicht:* +
Das Mitglied hat bereits drei offene Ausleihen (BR-008). +
→ Das System antwortet mit 409 MAX_AUSLEIHEN_ERREICHT. +
→ Use Case endet ohne Ausgabe.

*8a. Einweisung fehlt:* +
Die Kategorie ist einweisungspflichtig, aber für das Mitglied liegt keine gültige Einweisung für diese Kategorie vor (BR-010). +
→ Das System antwortet mit 409 EINWEISUNG_FEHLT. +
→ Use Case endet ohne Ausgabe. +
→ Karim verweist das Mitglied an den Wart für eine Einweisung.

*2a. Mitglied nicht gefunden:* +
Die angegebene Mitglieds-ID ist im System nicht vorhanden. +
→ Das System antwortet mit 404 MITGLIED_NICHT_GEFUNDEN. +
→ Use Case endet ohne Ausgabe.

*3a. Gegenstand nicht gefunden:* +
Die angegebene Inventarnummer ist im System nicht vorhanden. +
→ Das System antwortet mit 404 GEGENSTAND_NICHT_GEFUNDEN. +
→ Use Case endet ohne Ausgabe.

*Vorbedingung verletzt — Rolle fehlt:* +
Der Aufruf erfolgt ohne die Rolle `thekendienst`. +
→ Das System antwortet mit 403 ROLLE_UNGUELTIG. +
→ Use Case endet.

|Postconditions (Success)
a|
* Eine Ausleihe mit Status OFFEN ist im System gespeichert.
* Der Gegenstand hat den Status AUSGELIEHEN.
* Eine Kautionsbewegung HINTERLEGUNG ist im Audit-Log eingetragen (BR-022).
* Falls zuvor RESERVIERT: Die Reservierung ist auf ABGEHOLT gesetzt.
* Der Gegenstand wurde physisch an das Mitglied übergeben.

|Postconditions (Failure)
a|
* Es wurden keine Datenbankänderungen vorgenommen.
* Kein Gegenstand wurde ausgegeben.
* Kein Kautionseintrag wurde angelegt.

|Business Rules
|BR-004, BR-007, BR-008, BR-009, BR-010, BR-011, BR-020, BR-022, BR-026, BR-034, BR-035, BR-039, BR-041
|===

|1
|Ausleihe anlegen: `status = OFFEN`, `ausgabeDatum = heute`, `rueckgabeFrist = heute + Kategorie.leihdauerTage`, `verlaengert = false`

==== Anforderungen (EARS-Syntax)

[cols="1,4,1"]
|===
|ID |Anforderung |BR

|REQ-UC01-001
|When a request to POST /ausleihen is received with a role other than `thekendienst`, the system shall reject the request with HTTP 403 and error code ROLLE_UNGUELTIG without performing any state change.
|BR-039, BR-041

|REQ-UC01-002
|When a loan is created, the system shall set the `rueckgabeFrist` to the `ausgabeDatum` plus the `leihdauerTage` of the item's category, and shall set `verlaengert` to false.
|BR-011

|REQ-UC01-003
|While a member has at least one open loan whose `rueckgabeFrist` is before today and whose item has not been returned, the system shall treat the member as blocked and shall reject any new loan request for that member with HTTP 409 and error code MITGLIED_GESPERRT.
|BR-009, BR-034, BR-035

|REQ-UC01-004
|When a loan is successfully created, the system shall record a HINTERLEGUNG entry in the audit log containing the loan ID as `ausloeserId`, the computed `kautionEuro` as `betrag`, and the current timestamp.
|BR-020, BR-022

|REQ-UC01-005
|When a member already has three open loans, the system shall reject any further loan request for that member with HTTP 409 and error code MAX_AUSLEIHEN_ERREICHT. Pending Vormerkungen shall not count towards this limit.
|BR-008

|REQ-UC01-006
|If the category of the requested item has `einweisungspflichtig = true`, then the system shall verify that an Einweisung exists for the combination of member and category before proceeding, and shall reject the request with HTTP 409 and error code EINWEISUNG_FEHLT if no such Einweisung is found.
|BR-010

|REQ-UC01-007
|When the requested item has status WARTUNGSFAELLIG, the system shall reject the loan request with HTTP 409 and error code GEGENSTAND_WARTUNGSFAELLIG without altering any data.
|BR-026

|REQ-UC01-008
|When a loan is created for an item that was previously RESERVIERT for the same member, the system shall set that reservation's status to ABGEHOLT as part of the same atomic transaction.
|BR-007

|REQ-UC01-009
|When computing the Kaution, the system shall calculate 20 percent of the item's `wiederbeschaffungswertEuro`, round the result to the nearest whole Euro using commercial rounding (half up), and then clamp the value to a minimum of 5 Euro and a maximum of 100 Euro.
|BR-004
|===
