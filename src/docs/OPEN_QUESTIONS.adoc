== Product Owner

=== Q1.5  Success metrics

No quantitative success criteria (error-reduction rate, adoption target, transaction
volume) are stated anywhere in the code or README. +
*What does success look like for Release 1? What measurable outcomes should the system
achieve?*

=== Q1.6  Segment priority

Three user groups exist (Thekendienst, Mitglied, Wart). Their relative priority is
not documented. +
*If a design trade-off forces a worse experience for one group, which group's friction
matters most?*

=== Q2.5  Acceptance criteria — missing Gherkin files

The service comments and test files reference `spec-acceptance-criteria.adoc` and
`*.feature` files (e.g., `gegenstand-ausgeben.feature`) that are not present in the
repository. +
*Do these Gherkin feature files exist? If so, where are they? If not, have the
acceptance criteria been captured in another form?*

=== Q3.1.2  Formal stakeholder list

No formal stakeholder register is in the code. +
*Who are the stakeholders for this system beyond the three end-user roles? Are there
board members, auditors, or regulators who need access to the audit log?*

=== Q3.3.2  Origin of mitglied_id

`mitglied_id` is a plain TEXT field everywhere — no member table, no FK, no member
CRUD. +
*Where does a calling client obtain valid member IDs? Is there an upstream membership
system, a shared spreadsheet, or are IDs manually assigned at the front desk?*

=== Q4.3  Usability targets

No usability targets are in the code. A demo frontend exists but has no acceptance
criteria. +
*Are there response-time expectations, mobile requirements, or UX acceptance criteria
for the counter-staff workflow?*

=== Q4.4  Performance SLA

No response-time budget or throughput target is derivable from the code. Scale is
implied (400 items, 800 members, twice-weekly) but no target numbers are stated. +
*What is the acceptable response time for a typical issue or return operation?*

=== Q4.9  Priority among quality characteristics

No formal priority ordering is stated. Code structure suggests correctness first,
testability second, but this is inferred. +
*What is the priority ordering of correctness, traceability, security, and
performance for this system?*
