== Beschreibung

Als Thekendienst möchte ich einen neuen Gegenstand im System anlegen, damit er Mitgliedern ausgeliehen werden kann und alle relevanten Stammdaten (Inventarnummer, Kategorie, Wiederbeschaffungswert, Kaution) korrekt hinterlegt sind.

*Technischer Kontext:*

Eingehende Anfragen an `POST /gegenstaende` werden vom `GegenstandController.create()` entgegengenommen.
Dieser delegiert an `KatalogService.gegenstandAnlegen()`, das Validierung, Kautionsberechnung und Persistenz orchestriert.

Kautionsberechnung nach BR-004:

----
kaution = round(wiederbeschaffungswert * 0.20)   // kaufmännisch runden
kaution = max(5, min(100, kaution))               // Korridor [5, 100] EUR
----

Der Initialstatus eines neu angelegten Gegenstands ist `VERFUEGBAR`.

Validierungsregeln (BR-001, BR-003):

- `inventarnummer` — Pflichtfeld, String, systemweit eindeutig
- `kategorieId` — Pflichtfeld, muss einer existierenden Kategorie entsprechen
- `bezeichnung` — Pflichtfeld, non-empty String
- `wiederbeschaffungswert` — Pflichtfeld, positiver Ganzbetrag in Euro (≥ 1)

Fehlercodes:

- `INVENTARNUMMER_BEREITS_VERGEBEN` → HTTP 409
- `KATEGORIE_NICHT_GEFUNDEN` → HTTP 404

== Akzeptanzkriterien

[source,gherkin]
----
Feature: Gegenstand anlegen

  Scenario: Gegenstand erfolgreich anlegen mit regulärer Kaution
    Given eine Kategorie mit id "kat-1" existiert im System
    And der Thekendienst ist authentifiziert
    When er POST /gegenstaende aufruft mit
      """
      {
        "inventarnummer": "INV-001",
        "kategorieId": "kat-1",
        "bezeichnung": "Bohrmaschine",
        "wiederbeschaffungswert": 80
      }
      """
    Then antwortet das System mit HTTP 201
    And die Antwort enthält kaution: 16
    And die Antwort enthält status: "VERFUEGBAR"

  Scenario: Kaution wird auf Mindestwert angehoben
    Given eine Kategorie mit id "kat-1" existiert im System
    When der Thekendienst POST /gegenstaende aufruft mit wiederbeschaffungswert 20
    Then antwortet das System mit HTTP 201
    And die Antwort enthält kaution: 5

  Scenario: Kaution wird auf Höchstwert begrenzt
    Given eine Kategorie mit id "kat-1" existiert im System
    When der Thekendienst POST /gegenstaende aufruft mit wiederbeschaffungswert 600
    Then antwortet das System mit HTTP 201
    And die Antwort enthält kaution: 100

  Scenario: Inventarnummer bereits vergeben
    Given ein Gegenstand mit inventarnummer "INV-001" existiert bereits im System
    When der Thekendienst POST /gegenstaende aufruft mit inventarnummer "INV-001"
    Then antwortet das System mit HTTP 409
    And der Fehlercode lautet "INVENTARNUMMER_BEREITS_VERGEBEN"

  Scenario: Unbekannte Kategorie
    Given keine Kategorie mit id "kat-99" existiert im System
    When der Thekendienst POST /gegenstaende aufruft mit kategorieId "kat-99"
    Then antwortet das System mit HTTP 404
    And der Fehlercode lautet "KATEGORIE_NICHT_GEFUNDEN"
----
