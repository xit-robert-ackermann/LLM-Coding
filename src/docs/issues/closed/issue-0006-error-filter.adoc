== Beschreibung

Als Konsument der Leihgut-API möchte ich einheitliche Fehlermeldungen im Format `{"code":"FEHLER_CODE","message":"..."}` erhalten, damit ich Fehler maschinell auswerten und dem Nutzer sinnvolle Rückmeldungen geben kann.

Technisch wird eine Hierarchie von Domänenfehler-Klassen eingeführt.
`DomainError` ist die abstrakte Basisklasse; sie enthält einen `code`-Wert aus einem TypeScript-Enum sowie eine menschenlesbare `message`.
Konkrete Fehlercodes werden aus `src/docs/specs/interface-contracts.adoc` übernommen, z. B. `GEGENSTAND_NICHT_VERFUEGBAR`, `MITGLIED_GESPERRT`, `AUSLEIHE_NICHT_GEFUNDEN`, `RESERVIERUNG_ABGELAUFEN` u. a.
Ein NestJS `ExceptionFilter` (globaler Filter, registriert in `main.ts`) fängt alle `DomainError`-Instanzen ab und serialisiert sie als strukturiertes JSON; der HTTP-Statuscode wird je Fehlercode gemäß dem Fehlerkatalog in `interface-contracts.adoc` gesetzt.
Nicht-Domänenfehler (`Error`, unbekannte Exceptions) werden mit HTTP 500 beantwortet; der Stack-Trace wird ausschließlich geloggt, nie in den Response-Body geschrieben.
Der Filter ist eine reine Integration (IOSP): er mappt Exceptions auf HTTP-Responses, enthält aber keine Entscheidungslogik.

== Akzeptanzkriterien

[source,gherkin]
----
Feature: Globaler ErrorFilter und Domänenfehler-Klassen

  Scenario: Unbekannte Route liefert HTTP 404
    Given der Server läuft
    When ein HTTP-GET auf `/nicht-vorhanden` gesendet wird
    Then antwortet der Server mit HTTP 404
    And der Response-Body enthält das Feld `code`
    And der Response-Body enthält das Feld `message`

  Scenario: DomainError mit bekanntem Code liefert strukturiertes JSON
    Given ein Endpunkt wirft intern `new GegenstandNichtVerfuegbarError()`
    When der entsprechende HTTP-Request gesendet wird
    Then antwortet der Server mit dem für diesen Fehlercode definierten HTTP-Status
    And der Response-Body ist `{"code":"GEGENSTAND_NICHT_VERFUEGBAR","message":"..."}`
    And der Response-Header `Content-Type` enthält `application/json`

  Scenario: MitgliedGesperrtError liefert HTTP 409
    Given ein Endpunkt wirft intern `new MitgliedGesperrtError()`
    When der entsprechende HTTP-Request gesendet wird
    Then antwortet der Server mit HTTP 409
    And der Response-Body enthält `"code":"MITGLIED_GESPERRT"`

  Scenario: Unerwarteter Fehler liefert HTTP 500 ohne Stack-Trace
    Given ein Endpunkt wirft intern einen unbehandelten `Error('intern')`
    When der entsprechende HTTP-Request gesendet wird
    Then antwortet der Server mit HTTP 500
    And der Response-Body enthält kein Feld `stack`
    And der Response-Body enthält kein Feld `trace`
    And der Stack-Trace wurde ins Serverlog geschrieben

  Scenario: Fehler-Response ist immer JSON, nie HTML
    Given der Server läuft
    When irgendein Fehlerfall ausgelöst wird
    Then enthält der Response-Header `Content-Type` stets `application/json`
----
